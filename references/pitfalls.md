# Data Cinema 报告陷阱清单（实战踩坑，生成与自检时逐条对照）

本清单来自多轮真实返工，每条都是**曾经出错并被用户指出**的问题。生成后按「自检命令」段落逐条跑一遍。

## A. 数据摄取层

**A1 Excel 列偏移——表头必须逐列核对，不能按列数推算**
- 症状：销量/销售额整体翻倍或错位。
- 原因：表头月份列数量与预期不符时（如实际 24 个月却按 25 列切片），把销售额首列当成了销量末列。
- 做法：先打印 `hdr[0:N]` 与首行数据对齐核对，确认「销量起止列」「销售额起止列」「月份顺序（升序/降序）」三件事再计算。
- 尤其注意：源表常是**降序月份**（2026-09 → 2024-09），做趋势图前必须 `reversed()`。

**A2 标签数组与数据数组错位**
- 症状：横坐标写 8月~7月，数据却是 1~12 月顺序，每个月显示的都是别的月的值。
- 做法：标签数组与数值数组必须来自**同一次排序**；改排序时两个一起改，或干脆用 `{月: 值}` 字典映射后再排序输出。

**A3 财年切法不直观**
- 用户明确否定「2024-08~2025-07 vs 2025-08~2026-07」双年对比。
- 季节性一律：**自然月 1~12 排列 + 单年度柱状 + 全年月均金色虚线**，峰值月/谷值月用颜色区分（峰=coral，谷=rose，其余=cyan）。同比结论写进 insight 文字，不塞进图里。

## B. HTML 结构层

**B1 字符串替换丢闭合标签 → 卡片外框残缺**
- 症状：某张卡片的白色圆角边框"缺一块"，与相邻卡片粘连。
- 原因：用 `body.replace(旧文案, 新文案)` 改 insight/src 文字时，新字符串末尾漏了 `</div>`。
- 强制自检：构建后跑 `len(re.findall(r'<div\b', html)) == html.count('</div>')`，不等就报错中止。

**B2 Python 拼 `</script>` 写成字面量 → 整页空白**
- 症状：截图全白，什么都没了。
- 原因：在 Python 三引号字符串里写 `'</' + 'script>'`，拼接表达式被当字面量写进文件，script 永不闭合，后续整个 body 被吞。
- 做法：用 `chr(60) + '/script' + chr(62)` 或先把闭合标签存变量再拼接；构建后断言 `<script` 与 `</script>` 数量相等。

**B3 路径解析误匹配**
- `glob('cls_parts/part*.txt')` 配 `p.split('part')[1]` 会命中目录名 `parts` 里的 `part`，抛 `ValueError: invalid literal for int()`。
- 做法：排序键用 `re.search(r'part(\d+)\.txt$', p)`，别用 split。

## C. 布局与视觉层

**C1 入场动画 translateY 大于卡片间距 → 模块重叠**
- 症状：用户报「每个模块的外框没有独立显示，重叠到一起」。
- 原因：`.reveal{transform:translateY(28px)}` 而卡片 `mb-6` 只有 24px，动画过程中卡片下移压叠下一张。
- 做法：**入场动画只用 opacity 淡入，不做位移**（模板已改）。若一定要位移，必须 `translateY < 卡片间距`。

**C2 相邻卡片无间距（尤其"在末卡后再追加一张"时）**
- 症状：两张卡片白框紧贴、中间 0 间距（典型如 2.5 表格卡与 2.6 图表卡粘连）。
- 根因：规范是「同一 section 内除**最后一张**卡片外都要 `mb-6`」。当你往章节**末尾追加新卡片**时，原来的末卡（当初按"末卡"写的 `class="card p-6 reveal"`，**没有** `mb-6`）就变成了中间卡，必须补上 `mb-6`；否则新末卡与它贴合。这是追加卡片时最容易漏的一步。
- 做法：追加卡片后，把**上一张末卡**的 class 改成 `card p-6 reveal mb-6`，新末卡保持无 `mb-6`。
- 构建期强制自检（务必内置到 build 脚本，扫描 body/成品 HTML）：
```python
import re
for si,s in enumerate(re.split(r'(?=<section)', body)):
    if '<section' not in s: continue
    cards=re.findall(r'<div class="card p-6 reveal( mb-6)?">', s)  # group='' 或 ' mb-6'
    titles=re.findall(r'<h3 class="font-bold mb-1 text-lg">([^<]+)', s)
    n=len(cards)
    for i,mb in enumerate(cards):
        assert not (i<n-1 and not mb), f"缺间距: 第{si}节 卡片 {titles[i].strip()}"
```
- 推广：任何"在章节内增删/重排卡片"的改动后都要重跑此审计，因为末卡身份会随之改变。

**C3 长轴名与刻度/图例重叠**
- 症状：`yAxis.name` 写成「ABA排名(小=好)」「月销量(件·对数轴)」这类长文本，与顶部刻度或图例撞在一起。
- 做法：**轴含义写进图表标题（h3）**，`yAxis.name` 只留极简（如"月销量(件)"）或省略。

**C4 对数轴折线不要加 areaStyle**
- `type:'log'` 折线加面积填充会渲染异常。对数轴图一律纯折线。

**C5 英文数量级缩写（12.25M / 20k）—— 中文报告严禁**
- 用户明确指出：报告中不得出现 `12.25M`、`20k`、`$9.02M` 这类英文数量级表达，必须改为中文「万 / 亿」。
- 做法：统一用模板内置的 `fmtCN(v)` —— ≥1亿 → `2.75亿`；≥1万 → `61.7万`；<1万 → 千分位原值。轴标签 / tooltip / label / 正文数字全部走它（`fmtM`、`fmtK` 已改为它的兼容别名，输出同为中文）。
- 金额保留 `$` 符号、数量级仍用中文：`$902 万`、`$2.75 亿`。
- 百分比 / 倍数 / 小数值不受影响：`+18.3%`、`19.8×`、`3,808 件`。
- 构建期硬断言（已内置 build_report.py）：`re.findall(r'(?<![A-Za-z])[\$]?\d+(?:[.,]\d+)?\s*[MK](?![A-Za-z])', body_src + charts_src)` 必须为空，否则中止构建。

**C6 x 轴类别标签是长中文名、且个数 ≥8 → 必须倾斜 + 放大底部留白**

- 症状：9 个二级分类名（带 `B1`~`B9` 前缀，最长 13 个全宽字符）摊在 category 轴上，`rotate:0` 必然横向重叠；`bottom` 若沿用短标签图的值（如 56）会把标签切掉。
- 估算公式（卡片内容宽约 1100px，`max-w-6xl` = 72rem 减 padding，9 槽约 122px/个；中文全宽字符宽 ≈ 字号 px）：
  - 水平投影 = `字数 × 字号 × cos(角度)` ≤ 槽宽 → 13 × 10 × cos40° ≈ 100px < 122px ✓
  - 平铺则 13 × 10 × cos0° = 130px > 122px ✗
- 垂直占用 = `字数 × 字号 × sin(角度)` ≈ 84px → `grid.bottom` 至少给 **100**（`containLabel:true` 时标签落在 grid 内部）。
- 参考值：3 个短标签 → `bottom:56`；9 个 13 字标签 → `rotate:40, bottom:104`。
- 缩短标签（去掉编号前缀）是下策——会与同章其他图（treemap / legend 都用 `f.name`）命名不一致。**优先保一致性，靠参数解决**。

## D. 交互层（ECharts）

**D1 `tooltip.trigger:'axis'` 会绕过 series 悬停聚焦**
- 症状：配了 `emphasis:{focus:'series'}` 但悬停毫无反应。
- 原因：axis 触发接管了整个图表区的悬停（弹全系列数据面板），不再触发单条线的 emphasis。
- 做法：需要「悬停某条线→聚焦该线+只看它的数据」时，用**默认 item 触发**（不要覆盖 tooltip.trigger）。

**D2 主线 areaStyle 劫持全图悬停目标（最隐蔽的坑）**
- 症状：参考报告里效果正常，复制到新报告后"悬停任何位置都只聚焦同一条线"。
- 原因：参考报告的主线是**最下方**的线，面积块很薄；新报告主线是**最上方**的线，它的 areaStyle 覆盖整个绘图区，鼠标落在任何细线上实际命中的都是这块面积。
- 做法：**主线只在"位于图区底部/面积小"时才用 areaStyle**；否则一律不加，靠 `width:3 + symbolSize:6 + z:10` 区分主线。

**D3 blur 默认淡出不明显**
- 只写 `emphasis:{focus:'series'}` 时其余系列淡出很弱，用户会认为"没效果"。
- 必须显式：`blur:{lineStyle:{opacity:.08}, symbolSize:2}`，并给 emphasis 加粗 `lineStyle:{width: 原宽+2}`。

**D4 多系列配色数组长度要 ≥ 系列数**
- 症状：把 TOP6 扩到 TOP10 后，`lineStyle[6]` 为 undefined，颜色/宽度全崩。
- 做法：配色数组用 `pal.map((col,i)=>({color:col, width:i===0?3:1.8, z:10-i}))` 生成，或按 `i % pal.length` 取色，别硬编码 6 条。

**D5 图表 init 后再 `setOption({series: getOption().series})` 会吃掉坐标轴**
- 症状：散点/气泡图「横轴不见了」，纵轴或图例可能也在，极具迷惑性——同一 builder 里没这句的另一张图正常。
- 原因：拿 getOption() 处理后的 series 再 setOption 一次，等于局部覆盖重置了 axis 内部状态。
- 做法：mk/draw **一次成型**，绝不在初始化后回读再重设；双击还原用 `dispatchAction({type:'dataZoom',...})`，不要动 setOption。

**D6 气泡/散点图例色块与气泡不同色**
- 症状：legend 方块是默认调色盘色、气泡是自定义 alpha 色，对不上。
- 原因：legend 取 **series 级 `color`/`itemStyle.color`**；只在每个 data 项写 itemStyle、series 没顶层色时，图例回退默认。
- 做法：series 顶层设 `color:系列色`（不透明，供图例），data 项内再设 `itemStyle.color:系列色+透明度`（供气泡），两者同色。

**D7 单点极端值把气泡图压成一坨**
- 症状：四象限气泡「全挤在角落/一条线上」。
- 原因：某点小基数导致同比 +2000% 之类离群撑爆该轴；或半径按线性/单一除系数映射，量级差大时小点全叠一起。
- 做法：① 对超出稳健分位的轴值做**截断并在 tooltip 标「实际 X%，已截断」**（配 dataZoom 看全量），别让它决定轴域；② 半径用 **sqrt 按本图 min/max 归一到 10–52**；③ 同比类点先过「两窗口都有值 + 前窗口基数下限」，滤掉小基数伪高增长。

## E. 表格层
**E1 一个 ReferenceError 会静默杀掉后续所有渲染**
- 症状：某一张表空白，且它之后的所有表格/结论卡全部空白（图表因在表格之前定义所以还渲染，极具迷惑性）。
- 原因：用了未定义的格式化函数（如 `fnum`）。
- 做法：构建后断言脚本中引用的所有 `D.xxx` 键都存在；格式化函数集中定义在脚本顶部。

**E2 表头排序必须做数值解析**
- 直接按 textContent 排会把 `$9.80` 排在 `$19.32` 之后、`+113.9%` 按字符序乱排。
- 做法：`parseVal()` 剥掉 `$ % + − ,` 与 `K/M/万` 后缀换算成数值，`—`/空返回 `-Infinity` 沉底，非数值回落 `localeCompare(...,'zh')`。

**E3 明细表列名/口径**
- 多标签维度（节日/品种/颜色）份额加总会超 100%，必须在文末 APPENDIX · METHODOLOGY 口径说明与 src 行都写明"重复累积"口径。
- 中文翻译**并入英文名列**（`Wedding(婚礼)`），不单独开中文列。

**E4 模板脚本里的 `const` 存在 TDZ —— 图表代码必须插在 `const fpc` 之后（整页白屏级）**
- 症状：报告打开后**整页近乎全白**。HERO 大标题可见，但 KPI 卡片、所有图表区、结论卡全部不显示；浏览器控制台报 `ReferenceError: Cannot access 'fpc' before initialization`。
- 原因：模板主脚本里 `const fpc = ...`（表格百分比格式化器）声明在**靠后**位置（`fillTable` 之后）。若把图表配置插到它**之前**——例如插在 `/* 示例：横向正负条形涨跌榜 */` 这个示例块的位置——配置里对 `fpc()` 的调用会命中 TDZ（暂时性死区），脚本在该行中断；后续 `IntersectionObserver` 从未注册，`.reveal{opacity:0}` 永不解除，于是整页隐形。
- 做法：图表代码一律插在 `window.addEventListener('resize'` **之前**。此时 `const fpc` 已声明、IO 也已注册，即使图表代码再抛错，页面至少仍可读。
- 关键：`node --check` 与正则自检**都抓不到**（`fpc` 作为标识符语法完全合法），**必须做运行时检查**（见 F2）。

**E5 动态插入的 `.reveal` 元素不被已注册的 IntersectionObserver 观察 —— 整节「数据缺失」**
- 症状：某一节（典型是结论卡组 `#cards`）**整块空白**，但 DOM 里内容其实存在；页面其他部分正常。用户会描述为"XX 章节数据缺失"。
- 原因：`#cards` 的卡片是**脚本运行时**用 `innerHTML` 注入的，且带 `class="reveal"`；而模板的 IO 只在脚本里对**当时已存在**的 `.reveal` 做了一次 `querySelectorAll` + `observe`。后注入的元素不在观察列表 → 永远拿不到 `.in` → 永远 `opacity:0`。
- 高危区间：把图表/卡片渲染代码插到 IO 注册**之后**时必然触发 —— 修 E4（TDZ）时极易引入此回归。
- 做法（模板已内置）：IO 已暴露为可重入函数 `window.__observeReveal(root?)`；**任何动态插入 `.reveal` 的代码，末尾必须再调用一次** `window.__observeReveal()`。
- 自检：`runtime_check.js` 的 DOM 桩会解析 `innerHTML` 里的 `.reveal` 并投入元素池，最后断言「池中每个元素都曾 observe」，失败报「N 个动态注入的 .reveal 未被观察」。

## F. 验证方式（用户强约束）

**F1 不要擅自截图验证**
- 默认只做静态自查；需要截图时必须先征得用户同意，仅在静态手段无法定位问题时才申请。

**F2 静态自查清单（构建脚本内置，任一失败即中止）**

**F3 后台子任务进度判断**
- 子 agent 的 transcript 文件恒为 178 字节占位，**不能**作为进度信号；只看结果文件是否生成。批量任务某批超 30 分钟无结果文件即视为卡死，重启或改为对话内直接执行。

**F4 图表容器必须写成 `<div id="chN" class="chart">`，属性顺序不能反**
- 症状：自检报「仅配置=['ch9']」，即配置了但找不到容器；页面上那张图空白。
- 原因：手写 body 时习惯性写成 `<div class="chart" id="ch9">`，而自检正则 `r'<div id="(ch\d+)"'` 只认 id 在前的写法。
- 做法：统一 `id` 在前；或把自检正则放宽为「同一 div 标签内同时含 id 与 class」。两种都行，但必须一致。
- **推荐直接用放宽版正则**：`r'<div[^>]*\bid="(ch\d+)"[^>]*>'`，两种属性顺序都能匹配，不必强迫自己记住写法。表格同理：`r'<table[^>]*\bid="(tbl\w+)"'`。

**F5 模板残留的示例注释块会让自检误报**
- 症状：自检报「表格容器与填充不匹配：填充=['tblN']」，且 h3 数量比实际多 1。
- 原因：template.html 脚本区留有两段示例注释——`/* 示例：横向正负条形涨跌榜 … */` 与 `/* 明细表传第4参 true … fillTable('tblN', …) … */`。只替换了前一段时，后一段里的 `fillTable('tblN')` 和示例 `<h3>` 仍会被正则扫到。
- 做法：组装时两段都定位删除（用 `find('/* 明细表传第4参 true')` 找起点、`find('*/', k)+2` 找终点），别只删一段。

**F6 `SPL` 常量模板里没有定义**
- 症状：`ReferenceError: SPL is not defined`，一个错误静默杀掉后续全部图表与表格（与 E1 同源）。
- 原因：chart-recipes.md 的配色常量块写了 `const SPL = 'rgba(24,42,63,.08)'`，但 template.html 的 mk() 区没有它；模板自身用的是内联字面量。
- 做法：在注入的图表配置块**开头**显式 `const SPL='rgba(24,42,63,.08)';`。

**F7 insight 文案里的派生比例，必须单独算一次**
- 症状：正文写「单月已超过全年的三分之一」，实际是 28.5%；写「TOP50 占 78.2%」，实际 82.9%。
- 原因：只核对了聚合表里的**直接指标**，没核对文案里临时算出来的**派生比例**（占比、倍数、pp 差、峰谷比、象限计数）。
- 做法：落文案前把所有派生量单独 print 一遍；生成后再做一遍反向对账——把文案中每个关键数字用正则抓出来，逐个断言能在聚合结果里复算，不匹配即中止。

## G. 交付前内容自审清单（数字对了 ≠ 结论站得住）

> A–F 是**技术性**坑位（渲染、结构、数据摄取）。G 是**内容性**审查 —— 报告算得准、图也渲染正常，结论仍可能站不住。交付前逐条自问，任一不合格就不要交付。

**G1 分析对象是否属于同一可比范畴？**
- 把两类属性不同的商品放一起比"体量倍数"，读者会误以为同赛道。
- 做法：正文明确「主体 / 对照盘」，写清品类属性差异（如 B 含冷疗机等设备类、均价 $153），并声明"倍数仅用于判断量级，不构成同赛道竞争"。

**G2 样本筛选是否系统性剔除了高增长来源？**
- 为规避小基数而设的条件（如"上年度销量 < 200 则剔除"）常常正好把**新品**全剔掉。
- 实测案例：某报告剔除 91 个样本，其中 **55 个是全新品，贡献 13.3% 销量**；据此得出"增长靠头部拉动、不是普涨"，等于把这 13.3% 的高增长视而不见。
- 做法：必须披露被剔除样本的条数与销量占比；结论同时给"存量视角"与"含新品视角"。

**G3 重复计数是否只报了销量、漏报了条数？**
- 「同款不同色共享销量」这类问题，只算"销量多计 X%"不够 —— 均产、集中度、TOP N 占比全部以**条数**为分母。
- 做法：补报"唯一产品数"（实测：A 类 227 → 约 213 个、虚高 6.6%；B 类 1,295 → 约 1,171 个、虚高 9.6%），并点名哪些指标受影响。

**G4 同一个数字是否在两处承担不同含义？**
- 实测案例：KPI 卡写"峰谷倍差 17.4×"，正文写"1 月只有 17.4"（其实是季节指数）—— 数值撞车必然误读。
- 做法：全局搜关键数字，重复出现的逐个核对含义；不一致就换表述或加限定词。

**G5 术语是否精确？**
- 「谷值 ÷ 峰值」是季节性**振幅**，不是"抗跌性"；份额差 ≠ "溢价"（溢价看均价）。
- 做法：拿不准的术语换成描述性表述，不要套商业黑话。

**G6 趋势论断是否只有两个时点支撑？**
- 仅两个年度时点、且是跨品类比较，撑不起"增长在往 X 迁移"。→ 降级为"当期结构差异"，或补更多时点。

**G7 是否把"现象"直接说成"机会"？**
- "集中度低"既可能是机会，也可能是无序竞争 / 无品牌沉淀。→ 客观陈述指标，机会判断另行论证并给证据。

**G8 有无主观修饰词 / 未量化的程度词？**
- "**才**做出 28.1 万件"里的"才"、"仅"、"不过" —— 去掉，用数据说话。
- **更危险的是"小幅/略/显著/大幅"这类未量化的程度判断**：它们看似中性，实则在掩盖事实量级。
  实测案例：口径说明里写"新品会**小幅**推高分组同比"，复算后发现是 **15.5 个百分点**（剔除新品后 A 类同比从 +16.9% 掉到 +1.4%，即增长几乎全部来自新进入者）——"小幅"把一个关键结论写没了。
- 做法：凡出现程度副词，**强制替换为实测数字或占比**；替换时先跑一遍反事实计算（含 / 不含某类样本各是多少）。

**G9 中文报告是否混入英文数量级？**
- 禁止 `12.25M`、`20k`、`$9.02M`；构建期已有硬断言（见 C5）。

**G10 图表与正文口径是否一致？**
- 正文提"中位数"，但没说清是线性轴还是对数轴上的中位数 —— 两者数值差很多。→ 统一口径并注明。

---

**G11 章节 / 单图增删后，交叉引用是否全部同步？**

- 删掉**一整章**或**任意一张图**后，残留在**其他章节正文、结论卡「证据：」行、附录口径说明、页脚计数**里的引用会集体失效，且不会报错。
- 实测案例（单图版）：删掉「头部 20 名 vs 其余同比差」这张图后，结论卡里仍在引用它的 `+67.1% / −42.3% / 109.4pp`；删掉 B 类 TOP 50 表后，附录口径里仍写着「TOP 50 占比」。整章删除会更隐蔽。
- 实测案例：删除 03 章后，残留包括「3.1 散点图剔除了…」「3.3 与 3.4 的集中度」「远低于 A 类的 82.9%」「共 5 章 · 15 张图表」。
- 做法：
  1. 章节重编号（04→03、05→04）后，**同步改**：`sec-tag`、`h2/h3` 编号、结论卡证据行、附录口径编号、页脚章数/图表数；
  2. 删完跑一遍**关键词残留扫描**：把被删章节的所有小标题名 + 唯一数字（如 `17.4×`、`−24.2%`、`39.1%`）逐个 grep，命中数必须为 0；
  3. 图表容器 id 与 `mk()` 配置**不必跟着重编号**（id 是内部标识），但容器集合与配置集合必须**完全相等**——这条由构建脚本自动断言。
  4. 每张图的 insight 里，**凡引用被删图表数字的句子必须同步改写或删除**——最好的自检是逐条问「这句话的数字，现在还有哪张图/哪张表能溯源」。
  5. **新增了指标就要进附录公式表**：实测案例——给「二级分类明细表」加过两列衍生指标（老品同比、新品占比）后，附录公式表必须同步补上定义行，否则读者无法复算。**反向同理：删列时附录公式表里对应的定义行必须一并删掉**，否则读者会去找一个不存在的列。
  6. **新增一张图是删除的镜像操作，检查清单相同但更易漏**——实测案例：在 03 章第 3 位后插入「铺货密度」图（编号 3.4）后，需要同步的有：① 页脚「共 4 章 · **14** 张图表」的计数；② 该章后续编号顺延（明细表 3.4 → 3.5）；③ 附录里指向被顺延编号的引用（口径①「3.4 的在售 ASIN」→「3.4 铺货密度图与 3.5 明细表的…」、口径③「3.4 的「在售 ASIN」」→ 3.5）；④ 新容器 `id` 与 `mk()` 配置**必须同时加**（构建脚本断言两集合相等）；⑤ 新卡片若不是本章最后一张，**必须带 `mb-6`**（否则与下卡粘连，构建脚本断言）；⑥ 新 insight 里每个数字都要能复算。

**G12 删章节时，被删章节支撑的结论是否已迁移或作废？**

- 章节删掉 ≠ 结论作废。原挂在被删章节上的判断（如"头部 20 款占 63.3%"）要么另找图表承接，要么改写措辞。
- 做法：删完逐条问「这个数字现在还有图能溯源吗」。没有就二选一：迁移到保留的图表（例如把 A 类整体参考曲线并入新的集中度图）、或改为不依赖图表的定性表述并在 `src` 行注明数据出处。

---

**G13 衍生指标命名：别借行业黑话；同源指标不要并列成多列**

- **命名必须词义自明。** 实测案例——从零售业借来的「同店同比」（same-store sales）被用户直接质疑「这是什么玩意」。该词预设读者知道"门店"这一层，可报告里根本没有"店"，只有 ASIN；「同店 + 同比」两个词叠在一起、没一个字被解释过，表头只能靠猜。
- **做法：优先用报告里已经出现过、且已被 `src` 口径注解释过的词去配对。** 本例中「新品占比」先立住了，"新品 / 老品" 就是一对自解释的词 → 改名「**老品同比**」，读者无需任何背景知识。同理应避开的黑话：可比同比、存量同比、铺货率、动销率。
- **同源冗余检测：两个指标若分子相同、只有分母不同，就是同一事实的两次表述，不要并列成多列。** 实测恒等式：
  `新品占比 =（销量同比 − 老品同比）÷（1 + 销量同比）`
  三列并排（销量同比 / 老品同比 / 新品占比，实测推算与表中值逐行吻合到 0.1pp）逼读者自己做减法；砍到两列即可完全推出第三列。
- **自查三问：** ① 表头每个词，是否都能在 `src` 口径注里找到它**自己**的定义行？② 任意两列能否互相推导（能推 = 冗余，应合并）？③ 是否还有大量"XX 口径""XX 率"这类**没说清主体**的术语？
- **落地：删列 / 改名要同步五处**——① 表头数组 ② 行映射（删单元格，注意末项 `]` 前不能留逗号）③ `src` 口径注 ④ 图表 insight 文案 ⑤ 附录公式表。改完做**残留扫描**：旧词全文出现次数必须为 0，且被删列引用的**数字**（如本例 `26.5%`）也要全文 grep 归零。
- **注意 `build_data.py` 里的内部字段名（如 `yv_lfl` / `zvs`）在 data.json 里保留无害**——读者看不到，不必为改名去动数据层代码，避免误伤已核对过的数据口径。

---

**G14 口径变更（换分母 / 换分组）是「批量改名」的加强版：多查 5 类检查点**

- 触发：用户要求统一某个口径，例如「报告中所有的均销量都要取单月销量 > 0 的有数据的 ASIN」。
- **必查 10 处**（G13 的改名只涉及 5 处，口径变更多出 5 处）：
  1. 计算函数里的分母（`f.vti / f.n / 12` → `f.na`）；
  2. **图内系列的数据取值**——柱/线直接 map 的字段（`data:D.form.map(f=>f.n)` → `f.na`）。**只改分母不改柱子，图内会自相矛盾**：读者拿柱值算不出线值；
  3. 轴名 / 图例名（`name:'ASIN 数'` → `'在售 ASIN 数'`，本例 3 处）；
  4. 卡片 `h3` 标题；
  5. insight 文案里的**每一个数字**（本例 `317/207/123 件`、`2.6 倍` → `327/221/129 件`、`2.5 倍`，共 4 个数）；
  6. `src` 口径注；
  7. 附录公式表里的定义行；
  8. **结论卡里引用的同一组数字**——实测这组数同时出现在 2.2 insight 和结论卡② 里，最容易只改一处；
  9. **tooltip 的取数与标签**——tooltip 里的「ASIN 数」若仍是总数口径，读者拿它验算均产会算不通；改成「在售 ASIN 数：X（全部 Y）」既统一口径又不丢信息；
  10. 附录口径说明——补一句「本报告所有「均销量」类指标一律以「近 12 月销量 > 0 的在售 ASIN」为分母，另有 N 个零销量 ASIN 不计入」。
- **残留扫描必须防假阳性**：检测「还有没有 `f.n` 作分母」时，写 `"/ f.n /" in src` 会被 `"/ f.na /"` **前缀匹配**（`na` 以 `n` 开头）而误报。必须加词边界：`re.search(r"/\s*f\.n\s*(/|\)|;|,)", src)`。同类会互相污染的字段名还有 `f.n`/`f.na`、`yr`/`yr_lfl`、`yv`/`yv_lfl`。
- 旧数字扫描：`317`、`2.6 倍`、`79 个 ASIN` 全文出现次数必须归零。
