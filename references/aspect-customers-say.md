# 关注点三列分析模块（Customers say / Customers say 关注点 / CustomersReview）

> 记录如何用这三列**搭出一组关注点分析图**：数据怎么流、图怎么配、悬浮框怎么拼、哪些断言不能少。
> 全部阈值走变量，不含任何具体项目的数字。

### 设计前提

本模块的固定选择，**换报告 / 换品类都照此实现**（如需变更，须成套改，见「坑位 6」）：

1. **素材取自单个代表性产品**，不跨产品汇总；每个主图大类各配一条官方总结 + 一条评论原话。
2. 悬浮框统一走 `evTip(g, head, mode)` **三模式**（`sum` / `quote` / `both`），按图给不同素材。
3. **负向率榜展示的原话，其情感必须等于该大类的整体档位**（整体偏正面给正面原话、正负参半给中性原话、
   整体偏负面给负向原话）—— 这是本模块最核心的一条硬约束。

## 阅读方式

- **✅ 通用**：换品类照做。
- **🔧 需按数据调整**：方法不变，阈值 / 映射表 / 文案按当前数据重算。
- 本模块给的是**内容与逻辑**，**不绑定章节号与先后顺序** —— 落点见 §0.4。

## 0. 模块定位与前置检查

### 0.1 三列的分工

| 列 | 内容 | 角色 |
|---|---|---|
| `Customers say` | 亚马逊对整段评论的摘要 | 仅做体量画像 |
| `Customers say 关注点` | 结构化关注点 + 正负提及数 + 逐条判定 | **全部定量分析的唯一来源** |
| `CustomersReview` | 按关注点分段的评论原文 | **悬浮框的证据来源**（官方总结句 + 用户原话） |

**硬分工**：定量结论只能来自中间那列；原文只用来举证据，不参与统计（它没有次数口径）；
中间那列也不能直接当证据（它是聚合结果，不是谁的原话）。

### 0.2 本模块包含什么

三个可交付物，按**内容**命名（不是章节号）：

| 代号 | 内容 | 形态 |
|---|---|---|
| **图 A** | 大类热度榜 | 正负堆叠横条 + 官方总结悬浮 |
| **图 B** | 负向率榜 | 分档配色横条 + 评论原话悬浮 |
| **表 D** | 关注点明细表 | 全部归一标签，可排序 |

封面/摘要区的 KPI 卡（提及总量、标签数、覆盖率、正负占比等）也从这三列得出，按 HERO 规范摆放即可。

### 0.3 开工前四项检查（不通过就不要开始写正文）🔧

换品类时三列的**列位与内部格式都可能变**，先跑这段：

```python
# ① 三列齐全 + 取真实列号（不同品类列位不同，务必查表，不要写死索引）
COL = {h: i for i, h in enumerate(hdr) if isinstance(h, str)}
for need in ("Customers say", "Customers say 关注点", "CustomersReview", "父ASIN"):
    assert need in COL, f"缺列 {need}"
IDX = {k: COL[k] for k in ("Customers say", "Customers say 关注点", "CustomersReview", "父ASIN")}

# ② 同一父体下的多变体，三列内容是否完全相同 —— 决定「父体去重」口径成不成立
kids = {}
for r in rows:
    kids.setdefault(str(r[IDX["父ASIN"]]), []).append(r)
multi = {p: v for p, v in kids.items() if len(v) > 1}
assert all(len({str(k[IDX["Customers say 关注点"]]) for k in v}) == 1 for v in multi.values()), \
    "同一父体下多变体的关注点列内容不同 → 去重口径需重新确认"

# ③ 解析正则命中率 + 两列交叉校验（硬门槛，见下）
asp = {p: ASPECT.findall(str(unit_rep[p][IDX["Customers say 关注点"]])) for p in unit_rep}
assert all(asp.values()), "存在整行为空的父体 → 正则需按新格式重写"
for p, segs in REVIEW.items():
    miss = [t for t, *_ in asp[p] if t.lower() not in segs]
    assert not miss, f"{p}: 关注点 {miss} 在原文中无对应分段 → 两列不同源，不能并列使用"

# ④ 脏行与产物规模（决定后面人工核验的工作量）
print(f"[适配] 脏行 {dirty_n} 行 · 可用原话 {sum(len(v['quotes']) for v in REVIEW.values())} 条")
```

**② 为什么关键**：若多变体的三列内容不同，说明摘要按子体生成，按父体去重会错。

**③ 是硬门槛**：关注点列里的每个标签，都要能在原文列里找到同名分段，命中率 100% 才敢把两列并列使用。
不达标就说明两列口径不一致，悬浮框里**不能**声称「这条原话对应的就是这个关注点」。

### 0.4 落到报告哪个位置 —— 不预设章节号 ✅

章节号与先后顺序**由报告本身的叙事结构决定**，本模块不绑定。生成时按下面优先级决定：

1. **用户有明确指令** → 完全按用户的（指定章节、顺序、要哪几个图）。
2. **用户没指令，但源数据有其它分析维度**（如销量趋势、竞品对比、关键词）→ 先判断本模块在叙事里扮演什么角色：
   - 作为**主体分析**：单独成章，放在数据源审计之后、结论之前；图 A → 图 B → 表 D 是本模块内部的天然顺序
     （先讲「谈论什么」，再讲「口碑如何」，最后给全量明细兜底）。
   - 作为**补充视角**：只取图 A + 图 B 两图嵌进已有章节，表 D 可省。
   - 与销售/转化数据结合时：把「关注点 × 销售」的对齐分析放在本模块之后，或独立成章。
3. **仍然不确定** → **直接问用户**：要哪几个图、放在哪一章、是否需要二三级编号。
   **不要自己编一套编号就往下走** —— 章节号一旦写进正文就不好改，且交叉引用（「同 X.Y」）会连带失效。

落到正文时注意：

- 图表标题**按报告的「章.序」编号规则**取号（如所在章是第 3 章，则依次是 3.1 / 3.2 / 3.3），
  不沿用任何历史编号。
- 若省略表 D，编号要**连续**，不要留空号。
- 附录口径提示的序号同理，按该报告已有的提示条数续排。

## 1. 分析单元：父 ASIN 归并（去重口径）

```python
parents = collections.OrderedDict()
for r in rows:
    parents.setdefault(str(r[IDX["父ASIN"]]), []).append(r)

units, units_no = [], []      # 有 / 无关注点数据的父体
unit_rep = {}                 # 每个父体的代表行 = 第一个关注点列非空的子体行
for p, kids in parents.items():
    rep = next((k for k in kids if k[IDX["Customers say 关注点"]] and
                str(k[IDX["Customers say 关注点"]]).strip()), None)
    if rep: unit_rep[p] = rep
```

**所有下游统计一律基于父体**，不再回到行级。两个数字都要算出来写进正文——这是去重口径的证据，
不是可有可无的注脚：

```python
assert TOT == TOT_PARENT                       # 父体去重后总提及
kpi["mention_row"] = TOT_ROW                   # 按行直接求和
kpi["dup_factor"]  = round(TOT_ROW / TOT_PARENT - 1, 3)
```

句式固定为「按行 X 次 vs 按产品 Y 次，虚高 Z%，全篇一律采用去重口径」，让读者能自行判断口径差多少。

**覆盖率也要算** 🔧：

```python
cover_pct = round(len(units) / len(kids) * 100, 1)      # 有数据的父体占比
u12_share = round(sum(u["u12"] for u in units) /
                  (sum(u["u12"] for u in units) + sum(u["u12"] for u in units_no)) * 100, 1)
```

只要覆盖率 < 100%，正文就必须出现「结论只代表头部声音，不可外推至长尾」的限定句。
若同时存在「有数据组销量远高于无数据组」，则所有相关性观察都受样本截断影响，须一并标注。

## 2. 关注点解析与两级标签

### 2.1 单条关注点解析

```python
# 格式：标签(总提及) - N Positive / M Negative / 判定     🔧 换品类先验证格式
ASPECT = re.compile(r'([^()·]+?)\((\d+)\)\s*-\s*(\d+)\s*Positive\s*/\s*(\d+)\s*Negative\s*/\s*(\w+)')
def parse_aspects(s):
    return [(m[0].strip(), int(m[1]), int(m[2]), int(m[3]), m[4]) for m in ASPECT.findall(s or "")]
# 返回 (标签名, 总提及, 正向提及, 负向提及, 判定字段)
```

两个易漏点：

1. **字符类要排除记录分隔符**（这里是 `·`）。分隔符与标签名可能同形，不排除会把两条记录连成一个标签。
   🔧 换品类重新确认分隔符。
2. **解析完必须跑 §0.3 检查 ③**，命中率 100% 才算正则写对。

### 2.2 标签归一 → 语义合并（两级）

1. **归一**：`标签.lower()` 折叠大小写。不同品类的命名习惯不同，大小写重复往往更严重，
   归一后要报出「折叠掉几个」🔧
2. **语义合并**：人工维护映射表，把归一标签归入大类。**映射表逐品类手写，没有通用解** 🔧
   ```python
   LBL2GRP = {lab: g for g, labs in GROUP.items() for lab in labs}
   assert len(LBL2GRP) == LEN_RAW_LABELS, f"{len(LBL2GRP)} ≠ {LEN_RAW_LABELS}，映射表有漏项"
   assert len(raw_labels) == LEN_RAW_LABELS and TOT == TOT_PARENT
   ```
   > 断言里**必须写当前数据的实测值**。写死上一个项目的数字，后果是：真正的漏项错误被陈旧断言掩盖，
   > 或者反过来误报。
3. **展示名**：同一标签在不同产品下写法不一，取出现次数最多的原始写法：
   ```python
   def disp(k): return lab_canon[k].most_common(1)[0][0]
   ```
4. **大类粒度按品类定** 🔧：太少则失去聚合意义，太多则图挤。判断标准：主图大类数落在 10~18 之间。

### 2.3 主图门槛与两级输出

```python
MAIN_MIN = 100                                   # 🔧 按分位数定：让主图落在 10~18 个类
groups_main = [g for g in groups_sorted if grp_tot[g] >= MAIN_MIN]
```

`data.json` 同时输出两级：`groupsMain`（进主图）与 `groupsAll`（全部大类）。
**落选类必须在正文交代**（「其余 N 个低频类只保留在明细表中」），读者才知道你筛掉了什么。

### 2.4 两条必须写进口径的差异

- **重复累积**：一条评论可同时提及多个关注点 → **各大类提及占比加总 > 100%**，不可当互斥分桶读。
  这是全篇最容易被误读的地方，必须在正文和附录同时声明。
- **判定字段 ≠ 正负提及次数**：`关注点` 列每条记录末尾的判定（Positive / Mixed / Negative）是
  亚马逊对「这一条关注点」的定性；`N Positive / M Negative` 是**具体提及计数**。
  两者不同源，绝不可混用。二者数量级往往差几十倍，这个对比本身就是最佳论据。

## 3. 素材层：官方总结 / 评论原话 + 三模式悬浮框

这是图 A 与图 B 的核心差异点。

### 3.1 从原文列拆出总结句与原话

```python
SEG = re.compile(r"\*\*([^*]+)\*\*:")     # 🔧 确认分段标记是否仍是 **标签**:
# 一类脏行：把关注点列的统计串（"1,145 positive 147 negative …"）与总结句粘在一起
DIRTY = re.compile(r"[\d,]+\s+positive\s+[\d,]+\s+negative", re.I)   # 与品类无关，通用

def parse_review(txt):
    """`**标签**:总结句` + 换行 + 若干条真实评论。首行=官方总结句，其余=评论原话。"""
    txt = str(txt or ""); ms = list(SEG.finditer(txt)); out = {}
    for i, m in enumerate(ms):
        body = txt[m.end(): ms[i+1].start() if i+1 < len(ms) else len(txt)].strip()
        lines = [l.strip() for l in body.split("\n") if l.strip()]
        if not lines: continue
        out[m.group(1).strip().lower()] = {
            "sum": lines[0],
            "quotes": [l for l in lines[1:] if not DIRTY.search(l)],
        }
    return out
```

**「首行是总结句、其余是原话」这个假设必须用 §0.3 检查 ③ 验证**。
若首行也是评论，则「官方总结句」这个素材类型不存在，图 A 的悬浮框需要改设计。

### 3.2 整体情感档位（复用负向率榜的配色阈值，不另造口径）

```python
def _band(g, NEG_HIGH, NEG_MID):          # 🔧 阈值与图 B 的配色分档同源
    p = grp_neg[g] / grp_tot[g] * 100
    return "负面" if p >= NEG_HIGH else ("中性" if p >= NEG_MID else "正面")
```

**关键设计**：档位直接复用负向率榜的配色分档阈值，不引入第二套规则。
这样「图上的柱子是什么颜色，悬浮框里的原话就是什么口吻」，读者零学习成本。

🔧 换品类后必须看分布调阈值：若所有类都落在同一档，配色退化成单色，图就失去了分档信息量。

### 3.3 素材清单（EV_SPEC）与四条断言

人工逐条核验的清单，每个主图大类一条：

| 键 | 含义 |
|---|---|
| `s` | 官方总结句来源 `(产品, 标签分段)` —— 供图 A 使用 |
| `q` / `qk` / `ql` | 评论原话来源产品 / 反查片段 / 限定的分段标签 —— 供图 B 使用 |
| `qsent` | 该原话的情感标注（**人工核验，不是程序推断**） |
| `szh` / `qzh` | 中文语义概括（简洁优先，非逐字直译） |

```python
def _find_quote(parent, frag, want=None):
    """want 非空时优先在指定标签分段内查找 —— 数据源里存在同一句同时落在两个分段，
    不限定标签会反查到与目标大类无关的那个分段。"""
    segs = REVIEW.get(parent, {})
    order = ([want] if want in segs else []) + [l for l in segs if l != want]
    for lab in order:
        for q in segs[lab]["quotes"]:
            if frag in q: return lab, q
    return None, None
```

```python
assert qq, f"{g}: 未反查到原话 {spec['qk']!r}"                              # ① 片段必须命中
if spec.get("ql"): assert qlab == spec["ql"], ...                           # ② 落点分段与声明一致
assert spec["qsent"] == band, f"{g}: 原话情感与大类档位不一致"              # ③ ★核心
assert set(EV) == set(groups_main)                                          # ④ 素材覆盖 = 主图类集合
```

**③ 是图 B 的立身之本**：展示的原话情感必须等于该大类的整体档位。数据层断言 + 前端复核（§8.2）双重把关。

**④ 两个量都要用变量**，不要一边写死——漏改会让素材与图表静默错位。

**⚠️ 工作量**：EV_SPEC 是**纯人工**，等于「主图大类数 × 2 条素材」，每条都要读原句、判断情感、写中文概括。
主图类数超过 18 时成本会失控，此时要么砍类，要么改「自动挑选 + 抽检」——
但那样必须把抽检比例写进正文，不能让人以为全核过。

### 3.4 写进 `data.json` 的 `ev` 对象

`groupsMain[]` / `groupsAll[]` 每个大类挂一个 `ev`：

ev = {sum, sumFrom, sumSent, sumZh,            # 官方总结：句 / 来源产品 / 判定 / 中文概括

### 3.5 前端：`evTip(g, head, mode)` 三模式

```javascript
const SENT_ZH = {Positive:'官方判定：整体正面', Mixed:'官方判定：褒贬不一',
                 Negative:'官方判定：整体负面'};
/* 档位标签刻意与「官方判定」措辞错开（中性档用「正负参半」而非「褒贬不一」），
   否则读者会把报告自定义的负向率档位误认成亚马逊给的判定。 */
const BAND_ZH = {正面:'整体偏正面', 中性:'正负参半', 负面:'整体偏负面'};

function evTip(g, head, mode){
  const e = g.ev; if(!e) return head;          // ★ 无素材必须原样返回 head，不能崩
  mode = mode || 'both';
  // mode='sum'   → 仅「亚马逊官方总结 · 来源产品（官方判定）」   → 图 A 热度榜
  // mode='quote' → 仅「评论原话 · 来源产品（整体档位）」         → 图 B 负向率榜
  // mode='both'  → 两者都给（综合视图，默认不启用，留给需要同时呈现两种素材的图）
}
```

要点：

- 每个素材区**必须标注来源产品编号**与形态标签，读者才能判断「这是谁在说」。
- 英文原文与中文概括**都要给**（原文斜体、译文小一号字）。
- 拼接进 HTML 的文本一律过 `esc()`（评论原文含 `&` `<` `>`）：
  ```javascript
  function esc(s){
    return String(s).replace(/&/g,'&amp;').replace(/</g,'&lt;').replace(/>/g,'&gt;');
  }
  ```
- **图注必须写明悬浮框里能看见什么**，两图措辞不同：

| 图 | 调用 | 图注（`.src` 尾部） |
|---|---|---|
| 图 A 热度榜 | `evTip(g, head, 'sum')` | `<b>悬浮任意条</b>可查看亚马逊对该关注点的官方总结` |
| 图 B 负向率榜 | `evTip(g, head, 'quote')` | `<b>悬浮任意条</b>可查看评论原话——原话情感与该类整体口吻一致（整体偏正面给正面原话、正负参半给中性原话、整体偏负面给负向原话） |

## 4. 图 A · 大类热度榜 —— 正负堆叠横条 + 官方总结悬浮

**配置**

- 类型：横向堆叠条（`正向提及` 青 + `负向提及` 玫红），`yAxis` 倒序大类名
  （`groupsMain.slice().reverse()`），条尾 label 标该大类**总提及数**。
- tooltip：`trigger:'axis'` + `formatter` 取 `GM[ps[0].dataIndex]`，先给 5 个指标
  （合计提及 / 正向 / 负向 / 负向率 / 涉及产品数），再 `evTip(g, head, 'sum')` 追加官方总结区。

  > 这是**堆叠条形榜**：用 `trigger:'axis'` 是刻意的 —— 读者要一次读到该类目的正负两个数。
  > 也因此**不要给它加 `emphasis:{focus:'series'}`**，axis 触发下聚焦不会生效（见 pitfalls D1 的「适用范围」）。
- 高度按类数推导，不要写死：
  ```javascript
  const H = Math.max(400, groupsMain.length * 36);
  ```

**insight 模板**：第一名提及数＋占比＋对第二名的倍数、前 N 名合计与占比、负向率最高的三个类合计提及与占比。
三组数字互相咬合（一头讲体量、一头讲风险），结论自然落到「热度的钱在安全点上，风险集中在别处」这类结构判断。

**为什么只给官方总结**：热度榜回答「大家在谈论什么」，官方总结正是亚马逊对这个点的整体概括，
最贴合「谈论什么」的视角；塞入单条原话会让读者误以为是抽样证据。

## 5. 图 B · 负向率榜 —— 分档配色的横条 + 评论原话悬浮

**配置**

- 类型：单系列横条，按 `negPct` **降序**（负向率最高的排最上）。
- **配色即档位**，与 §3.2 同源，是全篇唯一的分档基准：
  ```javascript
  itemStyle:{color: g.negPct>=NEG_HIGH ? C.rose : (g.negPct>=NEG_MID ? C.coral : C.cyan)}
  ```
- `markLine` 金色虚线画分界点 🔧（默认取「正负各半」这个天然分界；
  若负向率整体偏低，该线会失去参照意义，应改用实际分位点）。
- 条尾 label 标 `xx.x%`；tooltip 先给负向率 / 负向计数 / 合计 / 涉及产品数，再 `evTip(g, head, 'quote')`。
- 高度同图 A 按类数推导。

**insight 模板**：≥高危档有哪几个（列具体数值）、居中的是哪几个、提及量最高的两个类的负向率 →
落到「**热度与口碑是两件事**」这类结构差异结论（而不是「A 涨 B 跌」的伪趋势）。

**为什么只给评论原话**：负向率榜回答「用户具体在抱怨/夸什么」，原话才是证据；
官方总结在图 A 已经给过，重复出现只会挤占篇幅。

**⚠️ 正面原话出现在负向率榜上是刻意设计，不是配错** —— 它回答的是「被整体认可的类，用户具体在夸什么」。
这句必须在附录口径提示里明写，否则一定会被读者当成 bug 上报。

## 6. 表 D · 关注点明细表 —— 全部归一标签可排序

这是「不丢信息」的兜底：主图只画少数大类，全部标签的全貌在这里。

```javascript
const rows = D.labels.map(l => {
  const tone = l.tot >= MAIN_MIN*3 ? '充足' : (l.tot >= MAIN_MIN ? '可用'
               : (l.tot >= MAIN_MIN/5 ? '偏薄' : '极薄'));
  return [
    (l.name.charAt(0).toUpperCase() + l.name.slice(1)),   // 展示名首字母大写
    l.grp,                 // 归入大类 —— 顺便让落选主图的低频大类仍可见
    fnum(l.tot), fnum(l.pos), fnum(l.neg),               // 千分位
    '<span class="' + (l.negPct >= NEG_HIGH ? 'neg' : '') + '">' + l.negPct.toFixed(1) + '%</span>',
    l.nUnit + ' 个',        // 涉及产品数 —— 样本强度的第一道闸
    tone
  ];
});
fillTable('tbl1', ['关注点','归入大类','提及数','正向提及','负向提及','负向率','涉及产品数','样本强度'],
          rows, true);   // 第 4 参 true = 可排序
```

- **样本强度分档以主图门槛为锚**（`MAIN_MIN*3 / MAIN_MIN / MAIN_MIN/5`），不要写死绝对值。
- 标题带排序提示：`<span class="src">(点击任意表头排序)</span>`。
- **insight 模板**：说明多少标签达到主图门槛、多少低于门槛中又有多少落在最薄档，
  并**点名**个别极端值（低提及 + 极高负向率 + 涉及产品数很少），防止读者拿着极薄样本的极端百分比下结论。
  建议把「样本强度」四档的**实际分布**直接写进 insight——低薄档占比越高，这个提醒越有说服力，
  比任何措辞都有效。

## 7. 附录必须补的口径提示 ✅

除了报告全局那几条，本模块**必须**单独补两条（序号按该报告已有提示续排）：

- **悬浮框分工**：逐图写明给的是什么素材；说明原话情感与整体口吻一致（正面类也给正面原话）；
  说明素材各来自一个代表性产品、**不等于该类全部产品的一致意见**；说明英文为源数据原文
  （含拼写差异与截断省略号）、中文为语义概括非逐字直译。
- **档位 vs 官方判定是两套口径**：「整体偏正面 / 正负参半 / 整体偏负面」是按负向率自定义的
  （与负向率榜配色同源）；「官方判定：整体正面 / 褒贬不一 / 整体负面」是数据源自带字段。
  前者按**提及次数**算，后者是对**整体口吻**的定性，两者不同向属正常现象。
  **「不同向的类数」必须由脚本反向复算**（§8.3）。

## 8. 三层校验（交付门槛）

### 8.1 数据层：断言即文档
把每个关键数字写成断言（标签数、总提及、正负提及、素材覆盖集合、原话情感 ↔ 档位）。
改口径时断言先炸，比事后对数字可靠。**断言里的数字必须是当前数据的实测值**。

### 8.2 前端悬浮框专项：`tooltip_check.js`

`node --check` 只验语法，正则自检只验字符串存在，**都抓不到 formatter 内部抛异常或返回畸形 HTML**
（formatter 只在鼠标悬浮时才执行——给图表加 hover 内容后，这是唯一的检查手段）。

做法：把 `report_charts.js` 里真实的 `esc / SENT_ZH / BAND_ZH / evTip` 切出来，在 `vm` 沙箱里
逐个大类 × 各模式执行：

| 校验 | 内容 |
|---|---|
| C1 模式隔离 | `'sum'` 只能出现官方总结区、`'quote'` 只能出现评论原话区、`'both'` 两者都有 |
| C2 情感一致 | `quote` 模式的档位标签 = 由 `negPct` 独立重算的档位；且**不得混入其它档位的标签** |
| C3 数据自洽 | `data.json` 里 `band === quoteSent`（数据层断言的前端复核） |
| 结构 | `div` 配平、分隔区存在、head 原样保留、英文片段与中文译文都在、来源产品可回溯 |
| 兜底 | 无 `ev` 时原样返回 `head`；未知 `mode` 不得抛异常 |

🔧 **检查器里不得硬编码**：循环遍历 data.json 的 `groupsMain`（不要写死类数），
档位从 `g.negPct` 现算（不要写死阈值），中文映射表从被测脚本里读（**另抄一份会跟着一起错**）。

### 8.3 数字反向对账
把正文纯文本里的每个数字抓出来，逐个断言能在聚合结果里复算。本模块专属的派生量：
第一名占比、前 N 大类占比、第一名与第二名的倍数、高危三类合计占比、
档位分布、**档位与官方判定不同向的类数**。

配套两条 `assert`：判定统计必须等于独立重算值；每个大类的原话情感必须等于档位推导值。
**排名类表述一律程序断言**，不手写「排第 N」。
注意剔除假阳性 token（ASIN / 章节号 / 文件名 / 月份），否则自检会被自己的章节引用卡死。
**章节号也是 token** —— 编号方案一改，正文的「同 X.Y」交叉引用要同步。

## 9. 本模块专属坑位

| # | 坑 | 规避 |
|---|---|---|
| 1 | 同一句原话落在两个分段，按片段反查会命中无关分段 | `_find_quote` 加 `want` 参数指定标签优先，并断言落点 |
| 2 | 原文列混入 `N positive M negative` 统计串，被当成评论原话 | `DIRTY` 正则过滤（特征与品类无关，通用） |
| 3 | 自定义档位与源数据判定字段**中性档撞名** → 自检误报、读者误认 | 档位中性档改叫「**正负参半**」，与官方判定的「褒贬不一」刻意错开 |
| 4 | 原话含 `&` `<` `>`，直接拼 HTML 会破版 | 一律 `esc()` |
| 5 | 有素材的大类数 < 图表大类数 → 悬浮框空白 | `if(!e) return head;` + 数据层断言 `set(EV) ==` 主图类集合 |
| 6 | 单产品锚点导致同一批产品反复出场，读者觉得「没做汇总」 | 这是本模块的既定取舍（每类各取一条代表性素材）。若确要汇总，改成跨产品聚合：按大类的判定分布取多数派、在多数派内挑提及最高且来源分散的句子，须**连带改写** `EV_SPEC` 字段、`ev` 结构、模式表、口径提示四处 |
| 7 | 正面档配了负向原话 | 断言 `qsent == band` + 前端反向复核 |
| 8 | 素材未标来源产品，读者无法判断代表性 | 悬浮框每个素材区强制显示来源 ASIN |
| 9 | 低频标签的极端负向率被当结论 | 明细表加「涉及产品数 / 样本强度」列，insight 点名提醒 |
| 10 | 换品类时沿用上一个项目的阈值与断言数字 | 全部阈值走变量；§2.2 / §3.3 / §8.2 三处的硬编码是重灾区 |
| 11 | **沿用别的报告的章节号**（本模块不叫「2.1 / 2.2 / 2.4」） | 按 §0.4 重新定位；省略某图时编号要连续，不留空号 |
